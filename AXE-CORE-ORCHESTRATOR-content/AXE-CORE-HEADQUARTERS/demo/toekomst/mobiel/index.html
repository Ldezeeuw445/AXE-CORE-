The Samsung, managed by AXE.

The phone already runs AXE CORE as its device manager: a Kotlin shell around the same web bundle as the Mac, with a native launcher, lock-screen cards and widgets. These screens bring it into the black look and the three materials — plate, card, smoked glass — and reorder everything the desktop can do into five tabs a thumb can reach.

▸ Device lock screen · the phone, managed · the launcher, kept ▸ Chat cards · voice · approve ▸ Core trading · memory · agents ▸ Link VPS · Mac · pairing ▸ Settings providers · voice & alerts · look & security
On the phone today Native shell · com.axecore.core, no git remote, one Mac. Six tabs in Kotlin: CORE CHART ALGO WEB CODE APPS — five open the web bundle, APPS is native. #/mobile in the bundle: its own black, its own card colour, filled cyan buttons, a four-button nav. Kept: lock cards, widgets, launcher with pins, on-device Gemma, offline queue, key after biometric unlock.
What changes One material language with the Mac: plate, card, glass; colour in letters and dots; glow only where it works. Five tabs, web and native the same: Device · Chat · Core · Link · Settings. Approvals first. The phone's main job is to answer what the Mac and the VPS are waiting on. Nothing new runs on the phone. Everything still goes through the VPS; the Mac is reached by relay.
  • ▸Frame: Galaxy S24-class, 412 × 915 CSS px, centred punch-hole, equal bezels. The docs mention an A17 at 384 wide — the layout is one column and survives that.
